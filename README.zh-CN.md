# Konoproxy 中文说明

Konoproxy 是轻量的 Omarchy 原生 Mihomo 代理插件。代码、注释、界面、
错误提示和默认文档全部使用英文；本文件是唯一的中文文档。
属于 [Konochi](https://github.com/xvvhang/konochi) 原生插件系列。

## 安装

需要 Omarchy Quattro、系统 Python 3.11+ 和图形化 polkit 授权代理。

```sh
omarchy plugin add https://github.com/xvvhang/omarchy-konoproxy-plugin --enable
```

启用插件不会自动安装内核或接管流量；内核安装需要在 Settings 中单独确认。
界面预览见 [README.md](README.md#preview)，测试记录见 [TESTING.md](TESTING.md)。

## 启用

将仓库放在 `~/.config/omarchy/plugins/konochi.konoproxy`，然后执行：

```sh
omarchy plugin validate ~/.config/omarchy/plugins/konochi.konoproxy
omarchy-shell shell rescanPlugins
omarchy plugin enable konochi.konoproxy
omarchy bar move konochi.konoproxy --section right
```

点击状态栏猫图标，选择 **Set up Mihomo**，阅读安装提示，再选择
**Agree and install**。插件会明确告知将下载固定版本内核、校验 SHA-256、
按需安装 `python-yaml`、创建并启动专属系统服务。开机自启单独选择。
安装操作需要管理员授权。可以明确选择启停免认证选项：只允许此账户的本地活跃会话
启动、停止、重启专属服务，不允许管理其他服务、修改服务文件或执行任意 root 命令。
安装、卸载仍需要管理员授权，同一账户的其他本地应用也能控制该专属服务。

已有安装可在 **Settings → Authorize service controls...** 中进行一次管理员授权。
这会安装受限的 polkit 规则并更新 root 持有的管理助手，不重启内核；
接受之前仍使用原来的认证方式。启用或更新插件不会静默修改系统授权策略。

安装后不会自动启用 TUN 或系统代理。请先导入并激活订阅，再选择接管方式。

## Just My Socks

登录 JMS 服务页面，在 **Subscription** 中复制专门的
**Mihomo / Clash.Meta YAML** 链接，在插件 **Profiles** 页面填写名称并导入，
再点击配置名称区域启用该配置。

支持订阅中兼容的 Shadowsocks、VMess、VLESS Reality 节点，保留 **JMS**
手动组和 **JMS Auto** 自动测速组。旧版 Base64 订阅不会发送到第三方转换站，
会提示改用官方 YAML 链接。

## 接管方式与路由策略

- **System proxy**：只影响遵循桌面代理设置的应用，不能保证终端请求被接管。
- **Tunnel proxy**：通过 TUN 虚拟网卡和路由接管流量，通常可以接管已有终端新建的连接，
  不需要修改终端环境变量。需要网络权限，可能与 VPN、防火墙冲突。
- **Traffic capture** 是互斥单选组：**System proxy / Tunnel proxy**。
  不再提供 Off 选项，需要停核时使用顶部开关；首次安装仍不自动接管流量，需手动选择。
- **Proxy mode** 是独立的单选组：**Rules / Global**，分别表示规则分流和全局代理。
  界面不再提供 Direct 模式，规则及 DIRECT 节点仍可用于直连。
- 主内核启停使用顶部的原生开关。

推荐你的使用场景选择 **TUN + Rules**。实际覆盖范围受路由、IPv6、
节点协议和其他网络软件影响。局域网目标不会自动排除 TUN，可按需添加直连规则。
TUN 检查不再把所有网卡一律当成冲突：已验证的 Tailscale 分流可共存，
但启用出口节点、默认路由、未知 TUN/WireGuard 或无法确认归属时仍会阻止切换。
仅只读检查 Tailscale，不会停用或修改它；其 IPv4/IPv6 组网地址绕过接管。
路由优先级调整到 Tailscale 之后、系统 main 表之前，下次应用配置时生效。

## 节点与规则

**Nodes** 按 profile 分组，不再展开或收起，也不重复列出每个策略组中的节点。
每组高度上限为 300 个缩放像素，超出后独立滚动，参考原生蓝牙面板。
直接读取本地配置及 provider 缓存，内核停止后仍正常显示；尚未下载的 provider
会明确提示缺少缓存。点击节点会切换其 profile，停核时先保存选择，下次启动再应用。
节点顺序沿用配置文件，不提供排序入口；分组和节点不再显示 Regions、Auto、Test 等动作按钮。
不再提供搜索；每组使用原生 section 标题和分隔线，不使用浅色背景卡片。
打开面板先测速再查询地区；等待结果的节点后显示旋转图标，测速结束立即显示结果，
不必等待地区查询结束。

地区不再通过节点名称猜测。Mihomo 的节点 API 没有标准国家字段，JMS 节点名也可能
不带地区，而且入口服务器 IP 的所在地未必等于节点出口所在地。

每次打开面板会自动刷新一次地区和延迟；切换标签页或常规状态刷新不会重复检测。
主内核停止、profile 未激活时也能检测。插件使用临时的普通用户 Mihomo 实例，经各个节点访问 Cloudflare trace，
读取出口 IP 的地区 `loc`，而不是 CDN 机房 `colo`。请求校验 TLS，最多两个探测并发，
并访问 Google 的 generate_204 端点测量延迟。单个临时实例复用于这两个请求，
并发不超过两个；后台检测不占用启停和节点切换操作。
不修改当前服务、节点选择或捕获方式，不配置直连回退。

地区显示 **US、UK、JP** 等代码，未验证显示 **--**。仅缓存地区代码、时间和配置指纹，
不保存出口 IP；临时探测配置权限为 0600，结束即清理。缓存超过七天会提示刷新，
节点配置变更后重新检测。检测失败不会覆盖原来的成功结果。
打开面板即会触发这些外部请求，不再逐次弹出确认。
Cloudflare 和 Google 会看到该节点的出口 IP；地理数据库可能误判，调试接口格式也没有稳定性保证。
链式 dialer-proxy 等暂不支持的节点保持未验证，不偷偷改用其他出口。

测速只做经过节点的 HTTP 延迟探测，不测试下载带宽。关闭面板即清空本次显示的
结果，关闭前尚未完成的测试也不会在重新打开后恢复显示。不会清除内核自身的健康检查历史。
关闭时取消排队检查，并在进行中的请求阶段结束后停止后续请求；临时进程有 40 秒超时保护。
相同配置去重检测，节点凭据或服务器变化后使用不同检测标识，避免显示旧配置的测量结果。

**Profiles** 使用与 Nodes 一致的无背景 section 和可选中行；点击整行切换配置，
勾选标记表示当前配置。编辑、刷新、删除放在同一个配置容器内，使用独立文字入口，
不会触发配置切换；点击名称区域切换配置。删除需要内联确认，
当前配置不能删除。
**Add profile** 和 **Edit...** 共用无卡片表单，暂时替代列表，使用持久字段标签及原生输入框。
编辑可修改名称或替换订阅地址、本地 YAML；来源留空则保持不变，已有订阅地址不会传到界面。
替换保留配置 ID、自定义规则及激活状态，经验证后事务性应用，失败保留原配置。
保存成功收起表单，失败保留输入；取消或关闭面板丢弃草稿。
节点、配置和模式切换不显示进度或成功提示，错误仍显示。
Settings 同样去掉背景容器，使用 section 标题和分隔线；订阅刷新周期改为
**Off / 6 hours / 12 hours / 24 hours** 互斥选项按钮。
内核管理与卸载合并，精简常驻说明，安全提示保留在对应确认表单中。
Settings 的 **Bar content** 仅保留两个独立、持久化开关：节点区域在上、上下行速度在下。
Bar 同样先显示区域、再显示速度。
默认全部关闭，仅显示图标；旧版的区域开关状态会保留，模式文字开关不再生效。
区域使用当前选中节点的已验证结果，未知显示 `--`；显示开关不会触发地区探测。
启用速度显示后，关闭面板也每两秒读取本地控制器；不会启动节点测速或改动接管方式。
关闭速度显示后恢复面板打开五秒、关闭三十秒的状态刷新。
图标使用原生 optical slot 宽度；区域和速度使用实际文字宽度，不再预留过大的示例文字空间。
点击划线跟随内容宽度，不包含外侧留白；仅图标时使用原生默认划线尺寸。
图标改为原创的 Clash 风格实心猫剪影，始终填充；TUN 生效时两侧炸毛，其他状态轮廓平顺。
R（规则）或 G（全局）以镂空胸章印在猫身正中央，不放在右下角。
停核或未接管时仅淡化猫；两种轮廓使用相同槽位宽度，切换不会改变图标尺寸。
启停不插入进度提示，模式说明和节点摘要保持稳定高度，避免内容跳动。
服务启停、流量接管和代理模式切换在控件内显示旋转过渡标记；命令完成后仍等待状态快照确认。
服务启停的旋转图标位于原生开关圆钮内部，跟随圆钮位置，自动适配大小并使用对比色；不再淡化整条开关。
失败恢复实际状态；命令完成后十五秒仍未确认时提示状态未知，避免一直卡在过渡状态。
所有动作不再显示通用的 Operation completed 提示，具体结果及错误仍保留。
Rules 按自定义规则、文件导入、远程规则集分 section，去掉背景卡片，编辑框只保留边框。
顶部标签固定，内容区域独立滚动。
界面不使用 accent 配色或写死圆角。首页去掉连接状态和浅色卡片，使用流量统计、
分隔线和模式选项。顶部使用标签页而非选项按钮；原生选项按钮只表达持久选中状态，
一次性动作改用无边框文字入口。

**Rules** 支持逐行输入 Clash 规则、导入本地规则文本文件、添加远程规则集。
自定义规则独立保存，更新订阅不会覆盖。配置需要先通过 Mihomo 校验才会应用，
控制接口拒绝配置时会尝试恢复上一份运行配置。

支持 6、12、24 小时自动刷新或关闭刷新。定时刷新依赖已启用插件的后台进程，
不是独立的常驻订阅更新服务。

## 卸载

请使用 **Settings → Uninstall...**：

- **No, keep core**：仅卸载插件，保留内核及服务，现有代理可能继续运行。
- **Yes, remove both**：恢复本插件管理的桌面代理设置，停用并停止专属服务，
  清理本插件路由、卸载托管内核、服务文件和专属授权规则，最后移除插件。
- **Cancel**：取消。

当前版本保留订阅和规则数据，也不会移除可能被其他程序使用的 `python-yaml`。
插件不会删除其他应用管理的代理内核和服务。

**重要限制**：Omarchy 当前没有插件卸载回调。直接运行
`omarchy plugin remove konochi.konoproxy` 或删除插件目录，会绕过上述询问，
并留下内核和服务。插件没有修改 Omarchy 的系统脚本来拦截这一行为。

## 安全与测试范围

内核和服务文件由 root 持有，内核进程以普通用户身份运行，仅获得必要的
网络管理能力；不会给用户可随意替换的二进制添加权限。控制接口只监听本机回环，
使用随机凭据。订阅与运行数据默认位于 `~/.local/share/konoproxy`，目录权限
为 0700，敏感文件为 0600。

当前一次只支持一个托管用户，不会静默升级已有内核。升级固定版本需要经过审核的
插件版本及明确的重新安装操作。托管配置不照搬订阅中的 DNS、监听器、控制接口、
TUN 设置或外部 UI 下载配置；仅支持 HTTPS 类型的远程 provider。

隔离单元测试和可选真实内核测试不会启用 TUN 或修改桌面代理。
真正的 TUN、管理员授权、开机启动、休眠恢复及卸载，需要在目标机器获得授权后验收。
完整技术说明、依赖、安装路径及诊断命令见 [README.md](README.md)。
